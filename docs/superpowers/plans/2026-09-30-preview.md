# Preview ao vivo (Parte 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `<pessoa>.<projeto>.bayerl.cloud` (só logado) e `<projeto>.bayerl.cloud` (público) servem o vite dev da pasta certa, ligam no acesso, desligam após 1h ocioso, e rodam isolados como o usuário `preview`.

**Architecture:** O Orion guarda o mapa host → porta → pasta (tabela `previews`) e escreve um `.env` por preview em `/srv/previews/`. Um script root (`sync-previews`) materializa o mapa em DNS, Caddy e units systemd. O systemd faz o liga e desliga (socket activation + `systemd-socket-proxyd --exit-idle-time`). O login usa um token curto de handoff e um cookie por host checado pelo `forward_auth` do Caddy.

**Tech Stack:** TypeScript/Fastify, vitest, systemd, Caddy 2 (`forward_auth`, `import`), API de DNS da Hostinger, vite.

**Spec:** `docs/superpowers/specs/2026-09-30-preview-design.md` (Parte 1)

## Global Constraints

- Nunca travessão em texto gerado.
- Nomes: pessoa = `users.name` minúsculo sem acento, só `[a-z0-9-]`; projeto = `projects.slug`. Host pessoal `<pessoa>.<slug>.bayerl.cloud`; host raiz `<slug>.bayerl.cloud`. Instância systemd = host sem `.bayerl.cloud`.
- Portas: socket em 9100 a 9999 (fixa por linha, nunca muda); vite em porta do socket + 10000.
- DNS: registro A explícito para 217.76.55.249, TTL 14400. Nunca wildcard.
- Ocioso: 1 hora. `preview.slice` `MemoryMax=3G`; vite `MemoryMax=600M`; swap 4 GB.
- Token de handoff: HMAC-SHA256 com `SESSION_SECRET`, validade 60 s, uso único. Cookie `orion_preview`: httpOnly, secure, host-only, 7 dias.
- Caddy devolve 404 para `/@fs*`, `/.env*`, `/.git*`, e query com `raw` ou `import` junto de `..` ou `%2e`.
- Tudo que precisa de root roda pelo `mcp__orion-root__exec`. Git via worktree de tarefa; publicar só pela fila; conferir no ar com `curl`.

## Review Focus

- Nome de pessoa com acento, espaço ou igual a um slug de projeto (`Laís Souza`, pessoa chamada `fisioexpert`): host precisa sair válido e único. Teste em Task 1.
- Clicar Preview numa sessão da raiz (sem worktree): o preview pessoal passa a servir a raiz, sem erro. Teste em Task 3.
- Token reaproveitado ou de outro host (link repassado): recusado. Teste em Task 2.
- Worktree cujo `package.json` mudou: não usar o symlink de `node_modules`. Teste em Task 3.
- `curl https://<host>/@fs/etc/passwd` e `/.env`: 404, inclusive no host raiz público. Verificação em Task 5.

### Task 2: Token de handoff, cookie por host e rotas de auth

**Files:**
- Create: `server/preview/auth.ts`, `server/routes/preview.ts`
- Modify: `server/index.ts` (registrar `previewRoutes`)
- Test: `tests/previewAuth.test.ts`

**Interfaces:**
- Consumes: `apontar`, `hostPreview`, `slugPessoa` (Task 1); `prepararPasta` e `escreverEnv` (Task 3), com a rota chamando os dois.
- Produces:
  - `assinar(dados: { u: number; h: string; exp: number; j?: string }, segredo: string): string` e `verificar(t: string, host: string, segredo: string, agora?: number): { u: number } | null`.
  - `consumirUmaVez(j: string, exp: number): boolean` (Set em memória com limpeza por expiração).
  - Rotas:
    - `GET /api/preview/open?session=<id>`: exige login do painel e dono da sessão (ou owner). Resolve projeto e `cwd`, chama `apontar` e `prepararPasta`/`escreverEnv`, e redireciona 302 para `https://<host>/__orion_auth?t=<token 60s com j>`.
    - `GET /__orion_auth?t=`: host tirado de `x-forwarded-host`. Valida e consome, grava o cookie `orion_preview` (token de 7 dias sem `j`, preso ao host) e redireciona 302 para `/`.
    - `GET /api/preview/check`: usada pelo `forward_auth`. Devolve 200 se o cookie é válido para `x-forwarded-host`, senão 302 para `https://v2.bayerl.cloud/`.

### Task 4: Infra da c3 (usuário, systemd, swap, sudoers) e sync-previews

**Files:**
- Create: `deploy/preview/preview.slice`, `deploy/preview/preview@.socket`, `deploy/preview/preview@.service`, `deploy/preview/preview-vite@.service`, `deploy/preview/instalar.sh`
- Create: `scripts/sync-previews.ts` (compila para `dist/scripts/sync-previews.js`)
- Test: `tests/syncPreviews.test.ts` (só a geração de texto)

**Interfaces:**
- Consumes: `garantirPreviews`, `instancia` (Task 1); `escreverEnv` (Task 3); token Hostinger via `getSetting(pool, KEYS.hostingerToken)`.
- Produces:
  - `blocoCaddy(p: PreviewRow, pessoal: boolean): string` (função pura exportada pelo script).
  - Comando: `node dist/scripts/sync-previews.js [--sem-dns]`, rodado como root.

Conteúdo fixo das units:
- `preview@.socket`: sem `ListenStream` no template (a instância é um nome, não uma porta, e socket não lê `EnvironmentFile`). O sync escreve um drop-in `/etc/systemd/system/preview@<inst>.socket.d/porta.conf` com `[Socket]\nListenStream=127.0.0.1:<porta>`.
- `preview@.service`: `Requires=preview-vite@%i.service`, `After=preview-vite@%i.service`, `EnvironmentFile=/srv/previews/%i.env`, `ExecStart=/usr/lib/systemd/systemd-socket-proxyd --exit-idle-time=1h 127.0.0.1:${VITE_PORT}`, `Slice=preview.slice`, `User=preview`.
- `preview-vite@.service`: `User=preview`, `Slice=preview.slice`, `MemoryMax=600M`, `StopWhenUnneeded=yes`, `EnvironmentFile=/srv/previews/%i.env`, `WorkingDirectory=${PREVIEW_DIR}` (usar `ExecStart=/bin/sh -c 'cd "$PREVIEW_DIR" && exec node_modules/.bin/vite --host 127.0.0.1 --port "$VITE_PORT" --strictPort'`), `ExecStartPost=/bin/sh -c 'for i in $(seq 120); do nc -z 127.0.0.1 "$VITE_PORT" && exit 0; sleep 0.5; done; exit 1'`, `NoNewPrivileges=yes`, `ProtectHome=yes`, `ReadOnlyPaths=/srv/projects /srv/worktrees`, `ReadWritePaths=` com o cache do vite (`${PREVIEW_DIR}/node_modules/.vite`).
- `preview.slice`: `MemoryMax=3G`.

`instalar.sh` (idempotente): cria o usuário `preview` (`--system --no-create-home --shell /usr/sbin/nologin`); `setfacl -R -m u:preview:rX` e `-d -m u:preview:rX` em `/srv/projects` e `/srv/worktrees`; `setfacl -m u:preview:x` só nos diretórios pai necessários; cria `/srv/previews` (dono danilo, leitura para preview); swap de 4 GB (`fallocate`, `mkswap`, `swapon`, linha no `/etc/fstab`) se não existir; sudoers `/etc/sudoers.d/orion-preview` com `danilo ALL=(root) NOPASSWD: /usr/bin/systemctl stop preview-vite@*` (validado com `visudo -c`); copia as units; `mkdir /etc/caddy/previews.d` e acrescenta `import /etc/caddy/previews.d/*.caddy` ao Caddyfile uma vez; `systemctl daemon-reload`.

`sync-previews`: `garantirPreviews`; para cada linha, grava `escreverEnv`, o drop-in da porta e `/etc/caddy/previews.d/<inst>.caddy`; garante o registro A pela API da Hostinger (`GET` da zona, e `PUT` com `overwrite:false` só para os que faltam); `systemctl daemon-reload`, `enable --now preview@<inst>.socket`; `caddy validate` e depois `systemctl reload caddy`. Erro num host registra e segue.

`blocoCaddy` (no arquivo real, envolver tudo depois dos matchers num `route { }`, para o Caddy seguir exatamente esta ordem em vez da ordem padrão das diretivas; `/__orion_auth` precisa responder antes do `forward_auth`):

```
<host> {
	@bloqueado path /@fs* /.env* /.git*
	@queryRuim expression `{query}.contains("..") || {query}.lower().contains("%2e")`
	respond @bloqueado 404
	respond @queryRuim 404
	handle /__orion_auth { reverse_proxy 127.0.0.1:3000 }                      # só pessoal
	forward_auth 127.0.0.1:3000 { uri /api/preview/check }                      # só pessoal
	reverse_proxy 127.0.0.1:<porta> {
		header_up Host "localhost"
		lb_try_duration 60s
		lb_try_interval 500ms
	}
	handle_errors { respond "Preview ligando ou com erro. Recarregue em alguns segundos." 503 }
}
```
